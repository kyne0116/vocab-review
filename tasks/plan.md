# Implementation Plan: 项目白皮书与文档体系重构

## Overview
以已确认的用户日常使用旅程为主线，重写项目白皮书，并将 docs/ 重构为“入口导航、产品正本、代理参考、开发过程、运维手册、ADR”六类职责清晰的文档体系。内容以当前代码、静态数据、逻辑测试和既有文档为事实来源，规划内容单独标注。

## Architecture Decisions
- 保留现有产品方案文件作为正本目录，新增代理指南作为代码检索与业务映射入口。
- 白皮书采用双层结构：第一层是账号初始化、拍照收词、学习、复习的端到端旅程；第二层是按业务域、状态、规则、数据键和代码入口的参考索引。
- `docs/README.md` 只维护地图、阅读顺序和文档规则；产品事实集中在白皮书及其正本，过程事实集中在开发过程。
- 文档明确标记“事实 / 推断 / 建议 / 待验证”，不把规划功能写成已实现。

## Risks and Mitigations
| Risk | Impact | Mitigation |
|---|---|---|
| 白皮书把规划写成当前能力 | High | 每章使用状态标签，并以代码/测试为事实来源 |
| 文档目录重构破坏旧链接 | Medium | 先保留既有产品方案路径，新增导航并修复入口引用 |
| 业务规则遗漏在页面实现细节中 | High | 使用 store、页面、测试三方映射表逐项核对 |
| 中文文件编码显示异常 | Medium | 新写文件统一 UTF-8，静态检查关键标题和路径 |

## Open Questions

# 拍照收词域

## 契约

图片进入 GLM 识别；GLM 内部带回退链（2026-11-21）：主配置免费 glm-4.6v-flash 优先，失败（429 限流/余额不足/网络错误等）按 `llm.config.js` 的 `fallbacks` 顺序依次切换收费 Key 重试（顺序靠前优先），任一级成功即返回，全链失败才进入 VisionKit OCR（鸿蒙端例外：微信鸿蒙版未实现 VisionKit，降级 VK 必败 errno=2003000，故 GLM 失败时不再降级，直接弹窗透出 AI 真实失败原因并引导重试或手动录入）。拍照/选图后先弹三选一菜单（直接识别 / 编辑后识别 / 按比例裁剪）：编辑用 wx.editImage、裁剪用 wx.cropImage（官方媒体能力，比例按图片方向自适应 4:3/3:4），确认后用新图进入识别，取消则放弃本张，接口不可用或失败时回退原图直接识别。候选页底部标注实际产出结果的识别路线（llm = 智谱 GLM 云端 / vk = 微信 VisionKit 本机）及照片去向，文案固定不随模型版本变化。文本经过候选提取、去重和噪声过滤，用户确认后批量查义。

候选勾选（2026-11-10）：识别新词与已收录词统一为可勾选。已收录词（当前账号有效库或拍照队列命中，忽略大小写）标「已收录」、不重复入库，默认勾选随本次会话整体学习（保持 R15「拍了就学」），用户可取消勾选——取消的已收录词不进入本次学习计划；已收录词不耗查义额度（释义音标取账号词库/队列快照）。只勾选已收录词时无需查义，候选页直接出现收录按钮（考前拍整页已学词表 = 生成纯复习批）。识别完成后可在候选页或查义结果页手动添加单词：仅接受英文单词/短语并按候选查重，已收录词同样默认勾选；候选页添加随批量查义，结果页添加即时单独查义（同有道接口），与拍照词走同一收录管线。查义失败的词不能收录。

手动录入（2026-11-10）：拍照收词页入口「手动录入单词」不经过识别，逐词输入（同一校验、查重与已收录规则）→ 批量查义 → 收录。手动会话与队列词条带 `manual` 标（见存储契约）；出批、复习、删除与其他会话同管线，页面以「✏️ 手动录入批 / 手动」标注区分拍照来源。照片会话保持顺序并作为整体批次优先。

## 代码落点

`pages/photo`、`utils/llm.js`、`utils/ocr.js`、`utils/wordParser.js`、`utils/lookup.js`、`utils/store.js` 的照片会话函数。

## 完成标准

候选、查义、收录、失败降级和账号隔离均有 L0/L1 证据；手动添加单词为页面级交互，各分支由 L2 模拟器验证；摄像头、隐私弹窗、真实网络和设备 OCR 只能由 L3/L4 证明。编辑/裁剪三选一菜单与识别路线标注为页面级交互：菜单与降级回退走 L2，wx.editImage / wx.cropImage 的真实编辑器行为只能由 L3 真机证明（2026-11-08 实现时模拟器未验证）。

2026-11-10（已收录词可选 + 手动录入）：store 层由 L1 场景 28 覆盖（勾选子集收录、纯已收录词会话、manual 标、跨账号隔离、冷启动重载 store、带手动会话来回切换零写入），495/0；页面分支由 Node 加载真实页面代码模拟 70 断言覆盖（默认勾选/取消/补选、修改与 AI 纠错换词后计数重算、纯已收录词直接收录、手动录入全链路、账号切换后各页面数据跟随），6 种变异全部被抓住。页面级交互的 L2 模拟器与 L3 真机表现（弹窗、键盘、点按手感）未验证。2026-11-11 用户在开发者工具（2.02.2609250）编译反馈「wx:else not found」：手动录入卡片插在 `wx:if`/`wx:else` 两卡之间断链，已移到不支持提示卡之后修复；同轮补 WXML 断链 L0 静态检查（11 个页面 wxml 全过），L2 编译待用户重新确认。已知范围外缺陷（未修，另行裁决）：结果页 AI 纠错换词后按候选旧拼写收录、换词结果被丢弃；`savePhotoSession` 在会话键未初始化的账号上首次调用会把新词重复包成 legacy 会话（生产路径首页 onShow 必先初始化，不可达）。

2026-11-21（鸿蒙端降级守卫）：用户鸿蒙真机最新体验版拍照报「VKSession 启动失败，errno=2003000」——LLM 主路线失败（免费模型限流/配额为高概率）后自动降级 VK，而微信鸿蒙版无 VisionKit 必败。修复：`recognizeImage` 降级分支加 `ocr.ohos()` 守卫，鸿蒙端不再调 VK，弹窗透出 AI 真实失败原因（限流 429/1305、网络 request:fail 等）并引导重试或手动录入；非鸿蒙端降级行为不变。改动仅 `pages/photo/photo.js` 降级分支（L0 走查），L1 526/0 无回归（该分支为页面逻辑、ohos() 依赖真机设备信息，L1 不覆盖），L3 鸿蒙真机验证待用户重新上传体验版后确认。

2026-11-21（GLM 回退链，同日第二轮）：用户真机截图确认根因为免费模型 429 限流。`utils/llm.js` 请求层加回退链——`chainFrom` 纯函数构建请求序列（主配置免费 glm-4.6v-flash 链首 → fallbacks 按序收费 glm-4.6v），`requestLLM` 逐级尝试、每级失败打日志切下一级、全链失败才抛最后错误；识别与 AI 纠错共用。`configured()` 语义放宽为「链非空即启用」（主 Key 无效时收费 Key 顶替）。两个收费 Key 写入本地 `llm.config.js`（gitignored，不入库），`llm.config.example.js` 模板同步 fallbacks 结构。L1 场景 31 覆盖链构建（无效项过滤、顺序、model 缺省、空链、收费顶替），535/0；请求级联依赖 wx.request，L3 真机（429 时日志显示切换且识别成功）待用户上传体验版后验证。

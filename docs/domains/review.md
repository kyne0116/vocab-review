# 正式复习域

每批次在学习日后的第 1、2、3、5、7、9、12、14、17、21 天安排十轮（R24，2026-11-23 起生效；改间隔对全部批次立即生效，已完成轮次不变，中途批次的下一次到期按新间隔计算）。前 3 轮复习全量，之后只复习遗忘池；正式复习中遗忘词连续两次答对才移出遗忘池，答错会重置连续答对次数。正式复习一次性提交；中途退出不保存部分结果。

R22（2026-11-15 审计）巩固循环：十轮完成后仍在遗忘池的批次不再结业断头——距该批**最近一次复习日**（`reviewHistory` 末条日期）满 `CONSOLIDATE_INTERVAL_DAYS`（7 天）即再产生一轮到期任务，只考池中词，连续答对 2 次出池、答错重置；池清空后彻底结业（不再产生任何任务）。`getDueBatches`、`getNextDueInfo`、`getReviewForecast` 与该口径一致；`reviewsDone` 在巩固轮继续递增（11、12…），轮次文案显示「巩固复习」，正确率按巩固轮口径（与遗忘轮同类）分段比较。

除到期调度外，用户可主动发起复习：教程总览页「复习 ▸ / 巩固 ▸」与复习中心「最需巩固 / 提前复习第 N 批」进入指定批次复习（`buildBatchReviewSession`，不依赖到期；已完成十轮但池非空的批次同样放行，池空的已完成批次仍拦截为 manualDone），答完同样经 `finishReview` 落库——推进该批复习次数、更新遗忘池与复习历史，不影响其他批次。错词本自由复习**答对 1 次即移出**错词本（用户主动自测，一次答对即信任——与正式复习「连续 2 次」的口径差异为设计取舍）、不推进复习次数；当日快测不推进复习轮次，但标忘的词落遗忘池（见学习域契约）。

代码落点：`utils/store.js` 的 `OFFSETS`、`CONSOLIDATE_INTERVAL_DAYS`、`buildReviewSession`、`finishReview`、统计函数；页面 `pages/review`、`pages/spell`。正式复习中，遗忘词必须连续两次答对才移出遗忘池；答错会重置连续答对次数。判定过程中**不**提前提示「已移出错词本」（移出发生在提交时、且正式复习只清本会话批次——R22 起结果页按 `finishReview` / `finishFreeReview` 返回的实际移出词数如实展示）。统计区分已学、复习中和已掌握（完成10轮且不在遗忘池）。验收：到期、逾期合并、逐词忘记、错词联动、巩固循环和自由复习隔离通过 L1。

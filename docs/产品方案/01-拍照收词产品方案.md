# 拍照收词产品方案

更新时间：2026-10-01 · 状态：**已确认**（R01–R04 已拍板：R01=A / R02=A / R03=A / R04=标灰提示「已收录」但不可收录；R05-A 已拍板 2026-10-01：智谱 GLM 视觉识别为主路线 + VisionKit 自动降级，见 `adr/ADR-002`）

## 整体流水线

```
拍照 / 相册选图（wx.chooseMedia，sizeType: original）
   ↓ 识别主路线（R05-A，2026-10-01）：智谱 GLM 视觉模型（utils/llm.js）
     压缩长边 ≤1600 → base64 → wx.request → 提示词约束输出 JSON 单词数组
     （教材拼写注记还原完整拼写 dialog(ue)→dialogue；未配置 Key/断网/失败/超时 → 自动降级 ↓）
     R06-A①（2026-10-01）：输出带自评注记 {w, note}——做过注记还原或低置信的词在候选页
     词下方灰色小字展示原图写法/低置信说明（透明化，零额外调用成本）
   ↓ 识别降级路线：本地 VisionKit（utils/ocr.js）
     小图（长边 ≤1280）先按短边 ≥640 放大（上限 3 倍）→ 超宽/超高按版面分块（块间少量重叠）
     → mode 2 静态检测 → VKOCRAnchor[].text（每块一条无分隔连串，见解析层粘连还原）
单词提取解析（utils/wordParser.js，两条路线产出统一走此层）
   ↓ 分词 → 只保留纯英文字母 token → 小写 → 去重（≥2 字母）
   ↓ 粘连还原（VK 路线主要）：标记边界切块 + 剥圈选符 + 词典切分（LLM 路线产出已是干净词，直通）
   ↓ 过滤：已在拍照生词本中的词；命中内置词库的词标灰提示「已收录」，不可勾选（R04 拍板：不收录）
批量查词（新增 utils/lookup.js，wx.request 并发 3~4 路，进度展示）
   ↓ 有道 jsonapi → { w, m（截断为 2~3 个义项）, p（美音音标） }
   ↓ 查词失败的词标记「待补义」，可重试或手动输入
   ↓ R06-A②（2026-10-01）：待补义词可「AI 纠错」（带原图核对拼写，建议经确认后重查）；
     候选页长按单词同样可 AI 核对；R06-B 开关 AUTO_FIX（默认关）开启后查义失败词
     自动拉取纠错建议（仅展示，点「改用它」生效）
用户确认页（词 + 音标 + 释义 复选列表）
   ↓「收录 N 词」
入库 → 写入「拍照生词本」动态词库（本地存储，快照即资产）
```

关键设计原则：

- **快照即资产**：翻好的词连同释义 / 音标存本地后不再依赖网络接口；即使将来接口变动，已收录的词完全不受影响（与现有「学习记录存快照」同一思路）
- **provider 抽象**：识别层 `recognize(imagePath) → [text]`（智谱 GLM ↔ VisionKit 自动切换）、查词层 `lookup(word) → {w, m, p}` 各自单函数接口，实现可替换（备胎：百度 OCR / 百度翻译）
- **降级安全网**：LLM 任何失败（未配置/断网/接口/超时/载荷过大）自动降级 VisionKit，不阻塞功能；`utils/llm.js` 的 `API_KEY` 置空即回到 VK-only 行为
- **释义截断**：有道义项很长，入库 `m` 取前 2~3 个义项，风格与内置词库一致（如 `v. 跳，跃；突然弹开 n. 春天；泉`）

## 数据与整合设计：拍照生词本动态账号

现有 `utils/store.js` 中账号绑定静态 `bank` 数组（`data/junior.js` / `data/primary.js`），批次 / 10 轮复习 / 遗忘池 / 错词本 / 总览全部基于它运转。整合方式（R01=A，2026-09-06 已拍板）：

1. `data/accounts.js` 增加第三个账号：`{ id: 'photo', name: '拍照生词本', dynamic: true }`（无 `bank` 字段）
2. `utils/store.js` 增加小函数并替换 `.bank` 引用点：

```js
function currentBank() {
  const acc = currentAccount();
  return acc.dynamic ? getPhotoBank() : acc.bank; // getPhotoBank 读 vocab_photo_bank 存储键
}
```

3. 收录 = 向存储键 `vocab_photo_bank` 追加 `{ w, m, p, addedAt }`，cursor 自动指向新词继续取批

**收益**：拍照词立刻获得完整的间隔重复流水线（35 词一批、10 次复习、遗忘池、错词本联动、教程总览、TTS 连读），**零改动复用全部现有页面**；`junior.js` / `primary.js` 保持纯净，历史进度不受影响。

> R01 备选 B（并入当前账号词库尾部，需为静态词库引入 `vocab_extra_<accountId>` 附加段并拼接 `currentBank()`）已否决：引入持久化附加段的复杂度，且打乱教材「按序学习」的节奏。

## 词条模型

```js
{ w: 'spring', m: 'n. 春天；泉 v. 跳，跃', p: 'sprɪŋ', addedAt: 1760000000000 }
```

- `p`（音标）是现有词库一直未用的可选字段，拍照词首批启用；复习 / 学习页已预留 phonetic 展示位
- 释义来自有道 `ec.word[0].trs`（分词性义项），与内置词库 `m` 字段格式同构

## 交互流程（v1）

1. 首页新增「拍照收词」入口 → 新页面 `pages/photo/`
2. 选择「拍照」或「相册」（`wx.chooseMedia`，sourceType 两种都开放）
3. 识别后展示候选单词复选列表（默认全选，可反选；命中内置词库的词标灰提示「已收录」且不可勾选）
4. 「查询释义」→ 进度条 → 列表显示 词 + 音标 + 释义（失败项标「待补义」，可重试 / 手填）
5. 「收录 N 词」→ 写入拍照生词本 → 提示成功 → 可跳转「拍照生词本」账号的新单词页开始学习

## 解析与过滤规则

- token 切分：非字母字符为分隔符；词内保留撇号与连字符（don't、T-shirt）
- 统一小写；过滤少于 2 个字母的 token
- 粘连还原（2026-10-01 真机日志定性后新增）：VK 静态模式把整块文本返回为一条无空格/换行连串、字母基本正确，圈选符 ○ 被识为大写 O / 数字 0 粘在词前。还原规则：① 词中「小写后跟大写」为粘连边界切块；② 块首剥圈选符（大写 O/数字 0 直接剥，小写 o 仅剥离后命中词典才剥）；③ 块内用词典（内置词库 + 拍照生词本）最长匹配切分——≤16 字母块仅接受无残段的完整分解（防词典短词误切真词，如 position→po+sit+ion），>16 字母块保留 2~16 字母残段为候选；④ 无标记超长串词典覆盖率 <1/3 按噪声丢弃并计数
- 粘连提示：候选 0 词且存在粘连串时弹「识别质量不足」引导重拍；有候选时页内提示「N 段连串文字被过滤，结果可能不完整」（2026-10-01，取代此前静默过滤）
- 去重：同图重复词、与拍照生词本已有词
- 内置词库命中：标灰提示「已收录」，**不可勾选、不收录**（R04 拍板结论，2026-09-06）；仍需在识别阶段加载内置词库做命中比对（600 词左右，内存无压力）
- 不做词形还原（went / getting 按原形收录；有道对常见屈折变化有独立词条，如 "go 的过去式"）

## 上线前合规清单（一次性）

1. mp 后台「用户隐私保护指引」：声明「**摄像头**」与「**选中的照片或视频信息**」两项（2023-09 起 `wx.chooseMedia` 强制要求，不配置真机拍照会被拦截）。入口：新版后台为左下角账号头像 →「账号设置」→「服务内容声明」→「用户隐私保护指引」（2026-09 实测）；旧版后台为「设置 → 服务内容声明」。提交后需微信审核通过才生效。**R05-A 追加（2026-10-01）**：指引中补充照片用于 AI 识别、上传第三方（智谱）的说明
2. 「request 合法域名」加入 `https://dict.youdao.com`（downloadFile 已有，request 是独立列表需分别配置）；**R05-A 追加（2026-10-01）**：再加入智谱开放平台 `https://open.bigmodel.cn`（以智谱官方文档为准，待真机验证 F9）
3. `utils/llm.js` 顶部 `API_KEY` 填入智谱开放平台专用 Key（低额度、可撤换；ADR-002 修订红线②的唯一豁免）
4. 最低基础库版本设为 ≥ 2.27.0（VK 降级路线要求；项目 libVersion 2.32.3 满足），或代码内 `wx.isVKSupport` 优雅降级
5. LLM 主路线模拟器可测（仅依赖 wx.request）；VK 降级链路必须真机调试（VKSession 在开发者工具模拟器大概率不可用）

## 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 智谱接口不可用 / 限流 / 费用异常 | 低~中 | 自动降级 VisionKit（用户无感）；`API_KEY` 置空回 VK-only；额度异常控制台撤换 Key |
| API Key 被反编译提取滥用 | 低（家庭流量小） | 低额度专用 Key；控制台可随时删除重建；仓库转公开前先撤换（ADR-002） |
| 部分低端机型不支持 VK OCR（降级路线） | 中 | `wx.isVKSupport` 检测 + 提示；百度 OCR 作 provider 备胎（退出条件见 ADR-001） |
| 有道 jsonapi 为非官方接口，可能变动 | 低~中 | 已入库词存快照不受影响；provider 抽象可快速切换 |
| 手写体识别效果差 | 高（确定） | 产品定位印刷体，拍照页加引导文案 |
| LLM 偶发漏词 / 幻觉编词 | 低 | 提示词强约束「只输出图中实际存在的词」；R06 自评注记透明化低置信词；待补义词「AI 纠错」带图核对；用户确认页是最后一道关 |

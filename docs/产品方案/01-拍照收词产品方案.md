# 拍照收词产品方案

更新时间：2026-10-03 · 状态：**已确认**（R01–R04 已拍板：R01=A / R02=A / R03=A / R04=标灰提示「已收录」但不可收录；R05-A 已拍板 2026-10-01：智谱 GLM 视觉识别为主路线 + VisionKit 自动降级，见 `adr/ADR-002`；**R15 已拍板 2026-10-03：拍照批 = 整次照片整体学习，已收录灰词随批学**，见「数据与整合设计」R15 节）

## 整体流水线

```
拍照 / 相册选图（wx.chooseMedia，sizeType: original）
   ↓ 识别主路线（R05-A，2026-10-01）：智谱 GLM 视觉模型（utils/llm.js）
     压缩长边 ≤1600 → base64 → wx.request → 提示词约束输出 JSON 单词数组
     （教材拼写注记还原完整拼写 dialog(ue)→dialogue；未配置 Key/断网/失败/超时 → 自动降级 ↓）
     R06-A①（2026-10-01）：输出带自评注记 {w, note}——做过注记还原或低置信的词在候选页
     词下方灰色小字展示原图写法/低置信说明（透明化，零额外调用成本）
   ↓ 识别降级路线：本地 VisionKit（utils/ocr.js）
     小图（长边 ≤1280）先按短边 ≥640 放大（上限 3 倍）→ 超宽/超高按版面分块（块间少量重叠）
     → mode 2 静态检测 → VKOCRAnchor[].text（每块一条无分隔连串，见解析层粘连还原）
单词提取解析（utils/wordParser.js，两条路线产出统一走此层）
   ↓ 分词 → 只保留纯英文字母 token → 小写 → 去重（≥2 字母）
   ↓ 粘连还原（VK 路线主要）：标记边界切块 + 剥圈选符 + 词典切分（LLM 路线产出已是干净词，直通）
   ↓ 过滤：命中当前账号有效词库或本账号拍照队列已有词的词标灰提示「已收录」，不可勾选
     （R04 拍板：不重复收录；R14 起按当前账号判定；R15 起队列已有词同样置灰展示——此前直接隐藏，灰词随批学）
批量查词（新增 utils/lookup.js，wx.request 并发 3~4 路，进度展示）
   ↓ 有道 jsonapi → { w, m（R07-A K12 精简：每词性块首个非噪声子义、≤2 词性、≤30 字，滤人名与语域标注）, p（美音音标） }
   ↓ 查词失败的词标记「待补义」，可重试 / AI 纠错 / 点「修改」改词重查
   ↓ R06-A②（2026-10-01）：待补义词可「AI 纠错」（带原图核对拼写，建议经确认后重查）；
     候选页长按单词同样可 AI 核对；R06-B 开关 AUTO_FIX（默认关）开启后查义失败词
     自动拉取纠错建议（仅展示，点「改用它」生效）
用户确认页（词 + 音标 + 释义 复选列表）
   ↓「收录本批」（新词 + 已收录灰词，R15）
入库 → 新词写入当前账号的拍照生词队列 + 整次拍照词单（含灰词）存为一个「拍照会话」（本地存储，快照即资产，R14/R15）
```

关键设计原则：

- **快照即资产**：翻好的词连同释义 / 音标存本地后不再依赖网络接口；即使将来接口变动，已收录的词完全不受影响（与现有「学习记录存快照」同一思路）
- **provider 抽象**：识别层 `recognize(imagePath) → [text]`（智谱 GLM ↔ VisionKit 自动切换）、查词层 `lookup(word) → {w, m, p}` 各自单函数接口，实现可替换（备胎：百度 OCR / 百度翻译）
- **降级安全网**：LLM 任何失败（未配置/断网/接口/超时/载荷过大）自动降级 VisionKit，不阻塞功能；`utils/llm.js` 的 `API_KEY` 置空即回到 VK-only 行为
- **K12 释义精简（R07-A，2026-10-01）**：有道整段义项最长近 200 字且含百科噪声（底夸克 / 人名 / 二击全倒），入库 `m` 精简为「每词性块首个非噪声子义、≤2 词性块、≤30 字」，风格与内置词库一致（如 `adj. 备用的，外加的；v. 抽出，拿出（时间、金钱等）`）；**不支持手动编辑释义**，释义只随改词联动更新——改词入口在**识别候选列表**行右侧红色「修改」（R08：初版长按 → 同日改查义页行内按钮 → 2026-10-02 前移候选页，改词发生在查义之前，改后重算「已收录」与勾选态，释义由「查询释义」统一获取）

## 数据与整合设计：拍照生词并入当前账号（R14 修订版，2026-10-02）

> **R14（用户拍板）取代 R01=A 的独立账号方案**：拍照生词不再作为第三个账号，收录直接进入**当前账号**。原方案的核心价值保留（拍照词获得完整的间隔重复流水线），取消的是「切到拍照账号才能学」的割裂，以及账号切换器 / 家庭榜里出现「词库型账号」的语义问题。

现机制：每个真人账号一条**拍照生词队列** `vocab_photo_words_<accountId>`（词条 `{ w, m, p, addedAt }`）：

1. **收录** = `store.savePhotoSession(list)`（R15；纯新词场景等价于 `addToAccountPhoto`）：与当前账号有效教材库、已有队列去重后追加
2. **学习** = `nextBatch()` 优先返回待学拍照会话（R15：会话整体成批、`photo: true` 标记、**不占教材游标**），学完自动回落教材顺序；总览待学批同序（拍照批在前，不与教材混批）
3. **删除** = `store.removeWords` 统一入口：拍照词从队列真实移除（已学的同步移出快照/遗忘池/错词本）；教材词走软删除 + 游标左移（R09 语义不变）
4. **「已收录」判定** = `store.inCurrentBank(word)`：命中**当前账号**教材有效库或本账号队列才标灰（另一教材的词允许收录进当前账号——不同孩子进度不同）
5. **迁移** = `store.migratePhotoAccount('junior')`（app 启动时执行一次）：旧 photo 账号数据（`vocab_photo_bank` / `vocab_records_photo`）迁入初中账号——未学词入队、学习记录追加（批次号接续、batchId 重生成、遗忘池/复习历史随迁）；源键保留 + `vocab_photo_migrated` 标记防重跑，误迁可清标记换目标账号重跑

### R15（2026-10-03 拍板）：拍照批 = 整次照片整体学习

> 用户需求：拍照时已收录的词保持灰色提示、不重复收录，但**新收录词 + 已收录灰词作为一次拍照的整体进入学习计划**（同样按账号隔离）。三点拍板：①以前拍过的词（队列已有）也置灰并随批学（此前直接隐藏不展示）；②拍照批**不设 35 词上限**，识别多少学多少；③接受尚未学到的教材词被拍照批学完后，静态批次走到时再学一遍（顺带巩固，不做跳过）。

在 R14 队列之上增加**拍照会话** `vocab_photo_sessions_<accountId>`（`{ id, createdAt, words }`，words = 该次照片完整词单快照，含灰词）：

1. **收录 = 建会话**：候选页整单（按出现顺序）交 `store.savePhotoSession(list)`——新词（已查到释义的勾选词）入队列并去重；灰词不入队列、不重复收录，词义音标直接取自当前账号词库/队列快照（**不耗有道查义与 GLM 额度**）；返回 `{ added, gray, total }` 供完成页展示
2. **出批 = 会话整体**：`nextBatch()` 取最早待学会话整体成批（`photo: true` + `sessionId`），**不受 35 词上限**；`saveLearnedBatch` 学完移除该会话；多会话按收录时间 FIFO
3. **纯灰词照片可成批**：考前拍整页教材词表 = 生成一个纯复习批（「拍照复习」场景）
4. **一词多批口径**：灰词同时存在于旧批与拍照批快照。复习调度本就按词去重（同天多批到期只复习一次、结果同步应用各批）、错词本按词聚合批次列表——天然兼容；**已学词数统计改为按词去重**（getStats / getPetInfo / getAccountsOverview / getOverview = 各批快照词集合大小，防宠物成长/家庭榜虚增）；词库页状态显示所在最新批次
5. **删除联动**：`removeWords` 同步过滤待学会话词单，会话删空则整会话移除
6. **旧数据迁移**：会话键首次读取时初始化，R14 队列中未学词自动包成一个历史会话继续优先学；`migratePhotoAccount` 迁移的未学词在会话键已初始化时同样补入会话

**历史（R01=A，2026-09-06 拍板，已被 R14 取代）**：曾以第三个动态账号 `{ id: 'photo', dynamic: true }` 承载拍照词，`currentBank()` 按账号分流，收益是零改动复用全流水线；当时否决的备选 B（并入当前账号词库尾部）顾虑是「持久化附加段复杂度 + 打乱教材顺序」——R14 的队列方案以「优先队列 + 内容快照」实现了合并意图而不打乱教材顺序。

## 词条模型

```js
{ w: 'spring', m: 'n. 春天；泉 v. 跳，跃', p: 'sprɪŋ', addedAt: 1760000000000 }
```

- `p`（音标）是现有词库一直未用的可选字段，拍照词首批启用；复习 / 学习页已预留 phonetic 展示位
- 释义来自有道 `ec.word[0].trs`（分词性义项），与内置词库 `m` 字段格式同构

## 交互流程（v1）

1. 首页新增「拍照收词」入口 → 新页面 `pages/photo/`
2. 选择「拍照」或「相册」（`wx.chooseMedia`，sourceType 两种都开放）
3. 识别后展示候选单词复选列表（默认全选，可反选；命中当前账号词库或拍照队列的词标灰提示「已收录」且不可勾选——R15 起灰词随批学，页内有文案说明；**每行右侧红色「修改」可改单词拼写**，确认后按有效内置库重算「已收录」与勾选态——R08③ 2026-10-02 入口自查义结果页前移至识别列表）
4. 「查询释义」→ 进度条 → 列表显示 词 + 音标 + 释义（失败项标「待补义」，可重试 / AI 纠错；不支持手动修改中文释义——释义只随英文单词联动更新，拼写有误回候选列表改词，R08；灰词不经查义，词义取自账号词库快照）
5. 「收录本批」→ 新词入队列 + 整次词单存为拍照会话 → 提示成功（新收 N + 已收 M 随批学）→ 可跳「新单词」优先学习该批（R15）
6. 词库管理入口在**首页**（不在拍照流水线内）：底部统计区「词库总量」→ 词库页，见下节（R09）

## 生词本管理（R09，2026-10-01；R09-2 全账号可删，2026-10-02）

对词库提供浏览 / 搜索 / 删除，处理误收录与不想学的词。**入口 = 首页底部统计区「词库总量」格**（初版放在拍照页 idle 阶段，同日依用户反馈调整——管理是词库维护动作，不属于拍照任务流）。

- **词库页按当前账号呈现**（首页统计即当前账号口径，数字与内容一致）：静态账号（初中 / 小学）= 教材顺序浏览；拍照生词本账号 = 收录时间倒序。**删除、搜索、勾选全账号开放**（R09-2 用户需求纠正：不限拍照生词本）
- **列表**：行 = 勾选圈（管理模式）+ 单词 + 音标 + 释义 + 状态标签（待学习 / 第N批·复习中 / 第N批·已完成）；点单词中英连读（同错词本）；大词库分屏渲染（默认 100 条，触底续载）
- **搜索**：匹配英文（不区分大小写）或中文释义子串，实时过滤；勾选状态跨搜索保留，「全选结果」作用于当前搜索**全部**结果（含未渲染部分）
- **删除**：行右侧红色「删除」按钮单删（确认弹窗）；右上「管理」进入勾选模式批量删（底部操作条：全选结果 / 删除选中）
- **删除语义（全账号、全量可删 + 联动清理）**：待学词移出后续学习；已学词（游标前）删除时游标左移，且从该账号各批次快照 `words` 与遗忘池 `wrongPool` 同步移除——后续到期复习与错词本自动不含该词；`reviewHistory` 历史统计保留。存储实现分两类：拍照生词本直接改写 `vocab_photo_bank`；静态库为**软删除**——删除集存 `vocab_deleted_<accountId>`，`bankOf(id)` / `currentBank()` 加载时过滤（源文件 `data/*.js` 不动，不可恢复）
- **拍照命中联动（R09-2）**：拍照收词的「已收录」命中与粘连切分词典均改用**有效内置库**（静态库剔除已删词）——用户从词库页删掉的内置词，拍照时不再标灰「已收录」，可重新收录
- **配套调度规则**：① `getOverview()` 已学批次按记录快照成章（不再按词库下标重切，顺带修复「末批不满后再收录」时总览错位，静态账号同样受益）；② 整批词条删空（words 与遗忘池皆空）的批次不再产生到期任务，批次壳保留（避免 batchNo 重排牵连历史引用）

## 解析与过滤规则

- token 切分：非字母字符为分隔符；词内保留撇号与连字符（don't、T-shirt）
- 统一小写；过滤少于 2 个字母的 token
- 粘连还原（2026-10-01 真机日志定性后新增）：VK 静态模式把整块文本返回为一条无空格/换行连串、字母基本正确，圈选符 ○ 被识为大写 O / 数字 0 粘在词前。还原规则：① 词中「小写后跟大写」为粘连边界切块；② 块首剥圈选符（大写 O/数字 0 直接剥，小写 o 仅剥离后命中词典才剥）；③ 块内用词典（内置词库 + 拍照生词本）最长匹配切分——≤16 字母块仅接受无残段的完整分解（防词典短词误切真词，如 position→po+sit+ion），>16 字母块保留 2~16 字母残段为候选；④ 无标记超长串词典覆盖率 <1/3 按噪声丢弃并计数
- 粘连提示：候选 0 词且存在粘连串时弹「识别质量不足」引导重拍；有候选时页内提示「N 段连串文字被过滤，结果可能不完整」（2026-10-01，取代此前静默过滤）
- 去重：同图重复词；跨次收录的重复由「已收录」置灰拦截（不重复写入队列/词库）
- 内置词库命中：标灰提示「已收录」，**不可勾选、不重复收录**（R04 拍板结论，2026-09-06；R15 修订：灰词随本次拍照会话整体进批学习）；仍需在识别阶段加载内置词库做命中比对（600 词左右，内存无压力）
- 不做词形还原（went / getting 按原形收录；有道对常见屈折变化有独立词条，如 "go 的过去式"）

## 上线前合规清单（一次性）

1. mp 后台「用户隐私保护指引」：声明「**摄像头**」与「**选中的照片或视频信息**」两项（2023-09 起 `wx.chooseMedia` 强制要求，不配置真机拍照会被拦截）。入口：新版后台为左下角账号头像 →「账号设置」→「服务内容声明」→「用户隐私保护指引」（2026-09 实测）；旧版后台为「设置 → 服务内容声明」。提交后需微信审核通过才生效。**R05-A 追加（2026-10-01）**：指引中补充照片用于 AI 识别、上传第三方（智谱）的说明
2. 「request 合法域名」加入 `https://dict.youdao.com`（downloadFile 已有，request 是独立列表需分别配置）；**R05-A 追加（2026-10-01）**：再加入智谱开放平台 `https://open.bigmodel.cn`（以智谱官方文档为准，待真机验证 F9）
3. `utils/llm.js` 顶部 `API_KEY` 填入智谱开放平台专用 Key（低额度、可撤换；ADR-002 修订红线②的唯一豁免）
4. 最低基础库版本设为 ≥ 2.27.0（VK 降级路线要求；项目 libVersion 2.32.3 满足），或代码内 `wx.isVKSupport` 优雅降级
5. LLM 主路线模拟器可测（仅依赖 wx.request）；VK 降级链路必须真机调试（VKSession 在开发者工具模拟器大概率不可用）

## 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 智谱接口不可用 / 限流 / 费用异常 | 低~中 | 自动降级 VisionKit（用户无感）；`API_KEY` 置空回 VK-only；额度异常控制台撤换 Key |
| API Key 被反编译提取滥用 | 低（家庭流量小） | 低额度专用 Key；控制台可随时删除重建；仓库转公开前先撤换（ADR-002） |
| 部分低端机型不支持 VK OCR（降级路线） | 中 | `wx.isVKSupport` 检测 + 提示；百度 OCR 作 provider 备胎（退出条件见 ADR-001） |
| 有道 jsonapi 为非官方接口，可能变动 | 低~中 | 已入库词存快照不受影响；provider 抽象可快速切换 |
| 手写体识别效果差 | 高（确定） | 产品定位印刷体，拍照页加引导文案 |

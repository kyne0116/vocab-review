## 2026-10-01：小图识别增强——压缩词表图仅识别 1 词的根因修复（待真机复测）

- **现象**：安卓真机「拍照收词」从相册选 `english.jpg`（USB 推送的压缩词表图），仅识别出 1 个候选 `ue`。
- **根因分析**（三轮证据链）：
  1. 图片实测 **963×246**（非相机原图），4x 放大逐像素检查：小写字高仅 ~8-9px、大写 ~9-11px，带 JPEG 压缩噪点；低于 VK OCR 可识别下限（项目文档已把「压缩到 1280 宽后字高 ~25px」定性为难图，本图再小 2-3 倍）。
  2. 963 ≤ 1280：不触发 2026-09-06 宽图分块修复（`regionsFor` 只在长边 >1280 时切块），全图单块送识别且 `loadImageData` 只缩不放——分块与放大两道缓解均未生效。
  3. 同款圈选词表（5×6 列、每词前置 ○）有失败先例：2026-09-06 实测 3000×826 原图即整行粘连成超长 token、被 `MAX_LETTERS=16` 全部静默过滤，仅 2 个 ≤16 字母碎片漏出（`markosticko` / `especiallyo`）。本次 `ue` 为 `dialog(ue)` 括号注记碎片（Node 实测 `tokenize(['dialog(ue)']) → ['dialog','ue']`，2 字母恰好通过 `MIN_LETTERS=2`）。
  - 结论定性：**主因 = 图片本身低于识别下限 + 圈选网格版式已知粘连边界；次要 = 宽图修复对 ≤1280 小图存在覆盖缺口、超长过滤静默折叠失败结果**。非代码逻辑 bug；VK 选型未被证伪（常规印刷页 F6 第七轮实测良好），ADR-001 退出条件未触发。
- **修复**（`utils/ocr.js`）：
  - 新增 `upscaleFor(width, height)`：长边 ≤ `MAX_EDGE`(1280) 且短边 < `MIN_SHORT_EDGE`(640) 的压缩小图按短边补齐放大，封顶 `MAX_UPSCALE`(3) 倍；大图返回 1 走原路径（回归零影响）。
  - `recognize` 以「放大后的有效尺寸」调用 `regionsFor`：963×246 → ×2.6 ≈ 2504×640 → 自然触发按列分块（5 块，L1 断言逐块尺寸），单块内字高 ~9px → ~22px。

- **可诊断性**（`utils/wordParser.js` + `pages/photo/`）：
  - `wordParser` 新增 `gluedCount(texts)`：统计将被 `MAX_LETTERS` 过滤的超长粘连 token 数。
  - 候选 0 词且存在粘连串：弹窗从「没有识别到单词」改为「识别质量不足——N 段连串文字，建议近距离重拍/换未压缩原图」；有候选但存在粘连串：候选页顶部提示条「N 段连串文字被过滤，结果可能不完整」。

## 2026-10-02：R07–R09 阶段经验总结（1.1.0 后四轮复盘）

功能已全部交付并实测通过（门禁 218→274），本阶段方法论层面的教训与可复用结论：

**产品/流程**

1. **入口与作用范围是拍板点，不是实现默认值**。本阶段三轮返工全部源于此：R08「修改」入口三次调整（长按 → 结果页按钮 → 候选页），R09 两次调整（拍照页入口 → 首页「词库总量」；静态库不可删 → 全账号可删）。教训：提方案时把「入口在哪个页面哪个位置、作用于哪个账号的数据」画出来让用户先拍板，能省掉整轮返工；实现者自行收紧边界（"静态库不可删"）大概率会被推翻。
2. **「实测反馈」是需求的最终形态**。长按可发现性不足、"右侧是待学习不是删除"、"`词库总量 ▸` 点不动"三个关键修正都来自用户上手后的第一句话；模拟器自查覆盖不了心智模型差异。小步交付 + 快速实测修正的循环比一次性做全更省。
3. **静默失败必须显性化**：`wx.navigateTo` 无 `fail` 回调时"新页面未进包"表现为点击无反应，浪费一轮排障；且「能看到新文案但功能无响应」≈ 增量编译未把新页面/JS 打进包（本项目已两次踩中），完整重新编译 / 清缓存是第一反应，关键跳转应带 `fail` 提示。

**技术**

4. **快照式数据模型是删除类功能的地基**：R01 拍板的学习记录存内容快照（而非引用词库下标），使 R09 删除已学词时无需任何数据迁移——批次快照过滤即可；同理 `getOverview` 改为按快照成章后，静态/动态账号、删词前后共用一套分章逻辑。追加式 + 快照式存储让"删"变成可组合操作。
5. **不可变资源 + 删除集 + 加载过滤 = 免构建链项目的通用软删除**：静态词库源文件不动，`vocab_deleted_<accountId>` 记删除集，`bankOf(id)` 统一过滤入口；下游（取批 / 总览 / 统计 / 拍照「已收录」命中）全部经由此入口取有效库，一处过滤全局生效，无需改动任何消费方。
6. **调度耦合点一次梳理清楚**：删除涉及五处耦合（词库、游标、批次快照 words、遗忘池 wrongPool、总览分章），`removeWords` 一个函数内闭环（游标左移 = 删除的已学词数；空批次壳保留避免 batchNo 重排牵连历史），37 + 15 条断言一次写全后，后续三轮需求调整零回归——**耦合密集的改动先把测试网织密，再动需求**。
7. **工具链坑（Agent 操作）**：bash 内联脚本中反引号会被命令替换吞掉（已损坏过正本一次，改用带引号 heredoc 或编辑工具）；Python 读写仓库文件须 `newline=''`，否则整文件 CRLF→LF 污染 diff。

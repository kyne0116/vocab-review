## 2026-10-01：小图识别增强——压缩词表图仅识别 1 词的根因修复（待真机复测）

- **现象**：安卓真机「拍照收词」从相册选 `english.jpg`（USB 推送的压缩词表图），仅识别出 1 个候选 `ue`。
- **根因分析**（三轮证据链）：
  1. 图片实测 **963×246**（非相机原图），4x 放大逐像素检查：小写字高仅 ~8-9px、大写 ~9-11px，带 JPEG 压缩噪点；低于 VK OCR 可识别下限（项目文档已把「压缩到 1280 宽后字高 ~25px」定性为难图，本图再小 2-3 倍）。
  2. 963 ≤ 1280：不触发 2026-09-06 宽图分块修复（`regionsFor` 只在长边 >1280 时切块），全图单块送识别且 `loadImageData` 只缩不放——分块与放大两道缓解均未生效。
  3. 同款圈选词表（5×6 列、每词前置 ○）有失败先例：2026-09-06 实测 3000×826 原图即整行粘连成超长 token、被 `MAX_LETTERS=16` 全部静默过滤，仅 2 个 ≤16 字母碎片漏出（`markosticko` / `especiallyo`）。本次 `ue` 为 `dialog(ue)` 括号注记碎片（Node 实测 `tokenize(['dialog(ue)']) → ['dialog','ue']`，2 字母恰好通过 `MIN_LETTERS=2`）。
  - 结论定性：**主因 = 图片本身低于识别下限 + 圈选网格版式已知粘连边界；次要 = 宽图修复对 ≤1280 小图存在覆盖缺口、超长过滤静默折叠失败结果**。非代码逻辑 bug；VK 选型未被证伪（常规印刷页 F6 第七轮实测良好），ADR-001 退出条件未触发。
- **修复**（`utils/ocr.js`）：
  - 新增 `upscaleFor(width, height)`：长边 ≤ `MAX_EDGE`(1280) 且短边 < `MIN_SHORT_EDGE`(640) 的压缩小图按短边补齐放大，封顶 `MAX_UPSCALE`(3) 倍；大图返回 1 走原路径（回归零影响）。
  - `recognize` 以「放大后的有效尺寸」调用 `regionsFor`：963×246 → ×2.6 ≈ 2504×640 → 自然触发按列分块（5 块，L1 断言逐块尺寸），单块内字高 ~9px → ~22px。

- **可诊断性**（`utils/wordParser.js` + `pages/photo/`）：
  - `wordParser` 新增 `gluedCount(texts)`：统计将被 `MAX_LETTERS` 过滤的超长粘连 token 数。
  - 候选 0 词且存在粘连串：弹窗从「没有识别到单词」改为「识别质量不足——N 段连串文字，建议近距离重拍/换未压缩原图」；有候选但存在粘连串：候选页顶部提示条「N 段连串文字被过滤，结果可能不完整」。
